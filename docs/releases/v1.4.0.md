# Transmission Telegram Bot 1.4.0

Version 1.4.0 is a security, runtime, and reliability upgrade. It moves the bot
to Python 3.14 and `python-telegram-bot` 22, hardens administrator onboarding
and secrets, modernizes the Transmission integration, and adds automated
regression and container checks.

## Highlights

- Python 3.14.6 and `python-telegram-bot` 22.8.
- Transmission 4.1.1 in the provided Compose deployment.
- Explicit administrator configuration; fresh bots can no longer be claimed by
  the first person who contacts them.
- Non-blocking tracker and Transmission operations, plus clean monitor-task
  shutdown.
- Correct local torrent metainfo uploads, including the fix for
  `Query failed with result "unrecognized info"`.
- No known vulnerable Python packages at release verification time.
- Fifteen regression tests plus Black, Flake8, mypy, dependency audit, and
  Docker build checks.

## Breaking changes

This is a major release and requires configuration updates:

1. Set a numeric administrator ID using `SUPER_USER`, `bot.super_user`, or
   `--super-user`. Startup fails if it is missing.
2. Docker Compose now requires `TOKEN`, `SUPER_USER`, `TRANSMISSION_USER`, and
   `TRANSMISSION_PASSWORD`.
3. Local execution and dependency locking target Python 3.14.
4. `Dockerfile.nas` has been removed. Mount configuration at
   `/usr/src/app/config/torrentino.yaml` instead of embedding secrets.
5. Proxy TLS verification is enabled by default. Install a trusted CA bundle
   for an intercepting proxy; use `proxy.verify_tls: false` only as a temporary
   compatibility measure.
6. New history entries use JSON Lines. Existing comma-separated records remain
   readable on a best-effort basis.

## Upgrade procedure

1. Back up `config/torrentino.yaml` and `download.log`.
2. Add the required administrator and Transmission credentials.
3. Validate configuration before starting:

   ```shell
   docker compose config
   ```

4. Pull the release image or build it locally:

   ```shell
   docker compose pull
   docker compose up -d
   ```

5. Check startup and service health:

   ```shell
   docker compose ps
   docker compose logs -f torrentino transmission
   ```

6. Verify `/help`, search, `.torrent` upload, magnet addition, torrent controls,
   user invitation, completion notifications, and clean shutdown.

See [UPGRADE.md](../../UPGRADE.md) for detailed migration and rollback guidance
and [CHANGELOG.md](../../CHANGELOG.md) for the complete change list.

## Verification

The release candidate was verified under Python 3.14 with:

- 15 passing tests;
- Black formatting checks;
- Flake8 linting;
- mypy static analysis across 29 source files;
- byte compilation;
- dependency vulnerability audit;
- Docker Compose validation; and
- a successful production-image build.

Live rollout should still begin with a staging bot and non-production
Transmission instance because tracker responses and external credentials cannot
be fully exercised in repository CI.
